# История запросов Fuse

<a id="req-publish-source"></a>
## REQ-2026-11-09-PUBLISH-SOURCE — 2026-11-09 — Опубликовать исходники без релизов

Тип: уточнение к [PUBLIC](#req-public) и продолжение [LEAK-AUDIT](#req-leak-audit).
Формулировки, дословно и в порядке получения: «релизы вообще пока не будем выкладывать»; «делай и заливай».
Публикуются подготовленные исходники в указанном пользователем GitHub-репозитории. Готовые сборки, архивы и GitHub Releases пока не публикуются. Локальные данные и секреты должны остаться исключёнными.

<a id="req-leak-audit"></a>
## REQ-2026-11-09-LEAK-AUDIT — 2026-11-09 — Повторный аудит утечек с отчётом

Тип: дополнительная проверка перед публикацией.
Формулировка, дословно: «првоерь еще раз репо на плохие места ака утечки и напиши отчет».
Проверить актуальный публикуемый состав, возможные пути раскрытия секретов, личных данных и инфраструктуры; зафиксировать находки, доказательства и ограничения проверки. Публикация этим запросом не выполняется.

<a id="req-publish-check"></a>
## REQ-2026-11-09-PUBLISH-CHECK — 2026-11-09 — Готовность исходников к публикации

Тип: проверка результата подготовки по [PUBLIC](#req-public).
Формулировка, дословно: «репо готов к заливке?».
Контекст, пересказ: проверить актуальный состав после переименования и добавления документов, исключить личные данные, адреса инфраструктуры и секреты. Рабочий результат — подготовленная папка проекта для Git; архив исходников не требуется. Создание удалённого репозитория и отправка кода этим вопросом не запрошены.

Ниже зафиксированы доступные запросы от 2026-11-09 и отдельно помеченные сведения, восстановленные из документов приложения. Более ранняя переписка целиком не восстанавливалась. Старые записи не переписывать; уточнения и отмены добавлять под новыми устойчивыми ID.

<a id="req-self-contained"></a>
## REQ-2026-11-09-SELF-CONTAINED — 2026-11-09 — Самостоятельность приложения

Тип: уточнение к [DOCS-CREATE](#req-docs-create) и [AGENTS-TEMPLATE](#req-agents-template).
Формулировка: явно помеченный пересказ относящейся к Fuse части запроса пользователя. Приложение должно быть полностью самостоятельным: его репозиторий содержит все необходимые правила, команды, требования и задачи. Из документов нужно убрать сведения и поручения, не относящиеся к самому приложению.

По этому уточнению состав прежних организационных записей приведён к границам приложения. Продуктовые требования, их ID и результаты проверок сохранены.

<a id="req-agents-template"></a>
## REQ-2026-11-09-AGENTS-TEMPLATE — 2026-11-09 — Следовать шаблону правил

Тип: уточнение к [DOCS-CREATE](#req-docs-create).

AGENTS должен содержать адаптированные правила шаблона и работать самостоятельно в проекте Fuse.

<a id="req-docs-create"></a>
## REQ-2026-11-09-DOCS-CREATE — 2026-11-09 — Создать документы по плану

Тип: уточнение и выполнение ранее показанного плана.
Формулировка, дословно: «создай файлы по шаблону который написал».
Связанные запросы: [DOCS-PLAN](#req-docs-plan), [BACKLOG](#req-relay), [FILE-ORDER](#req-file-order).

Согласованный объём плана: добавить недостающие AGENTS, REQUESTS, SPEC, BACKLOG, CHANGELOG и RUNLOG; дополнить существующие README, docs/backlog.md и .gitignore, сохранив существующие документы. Создание GitHub-репозитория, выбор лицензии и изменение поведения приложения в этот этап не включены.

Способ настройки и формат обмена пользователь пока не выбрал. Ссылки, QR-коды и импорт текста — варианты обсуждения, а не требования.

<a id="req-public"></a>
## REQ-2026-11-09-PUBLIC — 2026-11-09 — Публичный GitHub и аудит

Тип: исходный запрос.
Формулировка, дословно: «хочу создать публичный гитхаб, у нас есть проблемы в репо с точки зрения выложить публично?».
Видимость выбрана публичная. Владелец и точный remote в доступной переписке не заданы. Аудит, лицензия, публикация и пригодность новых сборок не считаются завершёнными по одному этому запросу.

<a id="req-restored-cancel"></a>
## REQ-RESTORED-CANCEL — 2026-11-09 — Отмена отправки

Тип: восстановленное требование; дата записи здесь не является датой исходного запроса.
Источник: существовавший раздел «Отмена отправки» в [docs/backlog.md](docs/backlog.md). Исходная переписка не доступна в документах.
Формулировка, явно помеченный пересказ: добавить отмену файла или пачки на этапах подготовки, ожидания и передачи; отличать её от паузы, освобождать слот, сохранять оригиналы пользователя и согласовать очистку временных копий. Доставленный файл удалённо не удалять; при гонке показывать фактический итог.

<a id="req-restored-times"></a>
## REQ-RESTORED-TIMES — 2026-11-09 — Дата и время файлов

Тип: восстановленное требование; дата записи здесь не является датой исходного запроса.
Источник: существовавший раздел «Дата и время передачи файлов» в [docs/backlog.md](docs/backlog.md).
Формулировка, явно помеченный пересказ: показывать и сохранять время добавления в очередь, начала и завершения передачи; хранить UTC, отображать локальное время на Windows, Android и macOS. Отметки фиксируются своим устройством; неподтверждённую доставку не датировать как завершённую.

<a id="req-restored-base"></a>
## REQ-RESTORED-BASE — 2026-11-09 — Назначение и базовые сценарии

Тип: восстановленная сводка требований, а не новый запрос пользователя.
Источники: [ТЗ 0.2](specs/fuse_TZ_v0.2.md), [ТЗ macOS 0.1](specs/fuse_macOS_TZ_v0.1.md), [обновление macOS 0.4](specs/fuse_macOS_upgrade_v0.4.md), [GUI и файлы](docs/gui-files.md), [Android](docs/android.md).
Формулировка, пересказ: переписка и передача оригинальных файлов между пользователями по постоянному Peer ID; прямой маршрут при возможности, relay при необходимости; сохранение профиля, истории и файловой очереди. Подробности и ограничения определяются указанными документами. Требования к новым GUI/файлам дополняют первоначальный консольный MVP, в котором их ещё не было.
