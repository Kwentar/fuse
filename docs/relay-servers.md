# Добавление relay-сервера

Нужен Linux-сервер с публичным IP, SSH-доступом для установки службы, systemd и свободным входящим TCP-портом (по умолчанию 4001). Сборка проекта сейчас подготовлена для Linux x86_64; для ARM64 нужна соответствующая сборка. Дополнительные пакеты на сервер для запуска Go-бинарника не требуются. У провайдера должны быть разрешены этот сервис и необходимый объём трафика.

Процесс `bootstrap-node` выполняет три роли:

- bootstrap: начальная точка подключения к сети;
- DHT: поиск подписанных контактных записей по Peer ID;
- Circuit Relay v2: пересылка зашифрованного трафика между клиентами, когда прямой канал недоступен.

Это не торрент-клиент и не VPN. Relay передаёт данные потоком, не хранит целые пересылаемые файлы. Серверу видны соединения и объём трафика, но содержимое клиентского Noise-канала зашифровано. При успешном LAN/direct файлы не идут через relay, хотя служебное согласование может обращаться к серверу.

## Размещение

Служба: `p2pmessenger-bootstrap.service`; бинарник `/opt/p2pmessenger/bootstrap-node`; конфигурация `/opt/p2pmessenger/config.json`; состояние и постоянный ключ сервера — `/var/lib/p2pm-bootstrap/data`. Исходный unit в `deploy/bootstrap-node.service`. Для нового сервера генерируется собственный ключ. Не копировать клиентские ключи на сервер и не публиковать серверный ключ; публикуется только Peer ID.

Конфигурация `configs/bootstrap.example.json` содержит шаблон. Нужно заменить `announce_addrs` на реальный публичный адрес, убедиться, что порт свободен, установить бинарник/unit, выполнить `systemctl daemon-reload` и `systemctl enable --now p2pmessenger-bootstrap.service`. Не перезапускать VPS и не менять другие службы. При существующем проекте сначала проверить его маркер и сохранить ID.

## Подключение клиентов

Публичный адрес сервера имеет вид `/ip4/IP/tcp/4001/p2p/PEER_ID`.

Добавить его в массив `relay_nodes` конфигурации каждого клиента. Если сервер также используется для начального поиска пользователей, добавить в `bootstrap_nodes`. Можно указать несколько серверов. Не заменять весь клиентский config.json фрагментом с двумя массивами: остальные поля должны сохраниться. SSH-данные клиенту не нужны.

Уже установленные приложения читают собственный config.json и не подтягивают изменения из исходников. После сохранения конфигурации перезапустить сетевой процесс; сначала дождаться завершения нужных передач. Профиль и identity.key не удалять. Windows по умолчанию использует `%LOCALAPPDATA%\P2PMessenger\config.json`; расположение Mac-профиля определяется его оболочкой. Android хранит профиль в закрытом каталоге приложения — миграцию серверов следует делать через обновление приложения/специальный импорт, не через удаление приложения.

`internal/config/default-network.json` задаёт встроенные серверы для новых профилей в будущих сборках. Изменение этого файла не меняет настройки уже запущенных клиентов.

## Настройка публичной сборки

В репозитории `internal/config/default-network.json` содержит пустые массивы. Общедоступные серверы проекта не предоставляются. Для собственной сборки укажите свои `bootstrap_nodes` и `relay_nodes` перед компиляцией; Android также упаковывает этот файл в assets. На Windows можно настроить эти массивы в `config.json` профиля после `init`.

Административные скрипты `deploy_initial.py` и `sync_default_network.py` сохраняют найденный адрес в `.local/default-network.json`, не изменяя исходники. Реквизиты для них задаются локально в `.env_server`: поля `ip`, `user`, `pass`. Эти файлы не входят в Git и архив исходников.

Для проверки собственного узла задайте `P2PM_RELAY_TEST_CONFIG` — абсолютный путь к локальному JSON с массивами `bootstrap_nodes` и `relay_nodes` (ровно один relay). Затем выполните `scripts/test-node.ps1 -Run '^TestDeployedRelay$' -Timeout 5m`. Тест создаёт временные профили и проверяет поиск, текст и файл 32 МиБ с SHA-256.
