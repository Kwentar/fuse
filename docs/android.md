# Android 0.4.2 preview

APK: `dist/android/fuse-0.4.2-preview-arm64.apk`. Сборка ARM64 для 64-битных устройств Android 8+. Это отдельный Android-интерфейс поверх того же Go-ядра, с новым файловым stream 2.1 и обратной совместимостью с Windows 0.2.0 / прежним Mac.

## Исправление LAN в 0.4.1

Локальные адреса для согласования прямого соединения теперь разворачиваются из слушающего порта с помощью Android-совместимого API anet. Раньше эта часть использовала стандартный net.InterfaceAddrs внутри libp2p, хотя проверка подсети уже использовала anet. На Android это могло давать пустой список LAN-адресов. Добавлены проверка разрешения wildcard listener и повторная проверка приоритета LAN. APK собран, подпись проверена; реальный LAN Windows ↔ Android требует проверки на телефоне.

## Обновление сетевых настроек

При первой миграции приложения адреса из `default-network.json` добавляются в начало `bootstrap_nodes` и `relay_nodes`; прежние пользовательские адреса сохраняются. Миграция выполняется один раз, без нового ID. `config.json` заменяется атомарно; ключ, контакты и история сохраняются. В публичных исходниках списки пусты: для собственной Android-сборки заполните их адресами своих узлов перед компиляцией. Фактический выбор relay зависит от доступности и libp2p.

Обновление поверх установленного приложения с сохранением данных требует прежнего ключа подписи. У участников должны быть совместимые настройки сети.

## Установка и запуск

Установите ARM64 APK поверх предыдущего приложения. Не удаляйте старое приложение и не очищайте данные: ключ профиля и ID сохраняются. Новому пользователю нужно создать ID и добавить собеседника; для приёма файлов добавьте друг друга. Разрешите уведомления сервиса, чтобы видеть работу в фоне.

В чате две разные кнопки: **«Фото и видео»** — системная галерея с множественным выбором, **«Файлы»** — документы любого типа. На современных Android используется Photo Picker; на старых — выбор документов с фильтром фото/видео. Максимум одной выборки задаёт Android, можно добавлять следующие пачки в ту же очередь. Также поддержаны «Поделиться» из галереи и файлового менеджера, в том числе несколько объектов.

Приложение не уменьшает фото и не перекодирует видео. У provider запрашивается исходный формат, включая HEVC/HDR. Передаются именно байты, которые выдал provider: если сторонняя галерея сама экспортирует отредактированный вариант, восстановить первоначальный файл приложение не может.

Входящие от добавленных контактов сохраняются автоматически в **Загрузки / P2PMessenger**, без подтверждения каждого файла. Через меню можно выбрать другую папку один раз. На Android 8/9 выбрать папку нужно перед автоматическим сохранением. Уже существующий файл не должен заменяться. Файл открывается только по вашему нажатию.

Очередь и ID сохраняются. Подготовка исходников выполняется в фоне; после копирования файл ставится в сетевую очередь. Две отправки активны одновременно, остальные ожидают. В списке видны размеры, прогресс, скорость и маршрут; в меню задачи — пауза/продолжение. Есть общий экран передач и отдельный чат для каждого контакта.

Для надёжного восстановления Android копирует исходящие файлы в частный outbox. Нужен свободный объём под выборку; после доставки в меню задачи можно удалить внутреннюю копию, не трогая оригинал. При приёме публикация в Downloads временно требует вторую полную копию; после публикации частная копия удаляется. Нет искусственного ограничения 4 МБ: 4 МиБ — размер одного блока.

Удерживать очередь в памяти приложение не требует, но при отсутствии постоянного доступа к URI после остановки процесса незавершённый импорт может потребовать повторного выбора. Уже подготовленные копии возобновляются независимо от URI. Android может остановить foreground service из-за системных ограничений/энергосбережения; тогда снова откройте приложение. Длительная работа на физическом устройстве остаётся ручной приёмкой.

## Сборка

Нужны portable Go из проекта, JDK 17, Android SDK platform 35 и build-tools 35.0.0. В текущем workspace они находятся в `.tools/android`. Системной установки Java/Android Studio не требуется.

```powershell
./scripts/build-android.ps1
# Или явно задать пути:
./scripts/build-android.ps1 -JavaHome C:\path\to\jdk17 -SdkRoot C:\path\to\android-sdk
```

Сборка использует javac → D8 → aapt2 → zipalign → apksigner. Gradle и сторонние Android UI-зависимости не нужны. Go ARM64 executable упакован в nativeLibraryDir как libmessenger.so, откуда запускается ProcessBuilder. Код не извлекается для исполнения в записываемый filesDir. Запуск на Android выполняется от UID приложения, без root. APK включает только ARM64, min API 26, target API 35; extractNativeLibs=true. Проверяются APK Signature v2/v3 и ZIP alignment.

Для закреплённого anet v0.0.5 нужен Go linker flag `-checklinkname=0`; это требование данной зависимости, а не отключение защиты Android. [Документация anet](https://github.com/wlynxg/anet).

Ключ подписи preview хранится только в `.local/android-preview.keystore`, не в исходниках или APK. Это тестовая подпись, не production-релиз. Для обновления без переустановки используйте тот же ключ; новый ключ потребует отдельного решения по миграции данных. ARM64 APK не содержит debug instrumentation и не помечен debuggable.

## Проверки и ограничения приёмки

Ниже приведена историческая сводка. Для новой сборки повторите проверки со своей инфраструктурой; списки серверов в публичных исходниках пусты.

- Go-тесты общего ядра проходят после изменения определения LAN-адресов.
- ARM64 APK собран; подпись и манифест проверены.
- На изолированном эмуляторе Android 15 x86_64 приложение запущено в собственном app UID, создан постоянный ID, сетевой сервис вышел online.
- Инструментальный тест Windows ↔ Android через существующий публичный relay: текст в обе стороны, файл 20 МиБ в каждую сторону, полный SHA-256 проверяется обоими получателями.
- Повторный прогон прошёл: потоковый импорт через content URI, пауза/продолжение и ещё один обмен файлами по 20 МиБ в обе стороны с проверкой SHA-256. Тест воспроизводится из `android/test`; локальные отчёты не публикуются.
- Интерфейс просмотрен по скриншоту эмулятора. Пользовательский системный файловый диалог, фон после долгого сна, локальное обнаружение и NAT на физическом устройстве требуют проверки на телефоне.
- Фактические 10 ГиБ ранее проверены общим Go-ядром на Windows. **Передача 10 ГиБ на физическом устройстве пока не проверена**; не путать это с проверкой метаданных или эмулятором.

Воспроизведение эмуляторного теста: SDK emulator, system-images;android-35;default;x86_64, NDK 27.2.12479018; запустить свой изолированный AVD как emulator-5554, затем:

```powershell
./scripts/build-android.ps1 -Emulator
./scripts/android-integration.ps1
```

Эмуляторный APK отдельный: debuggable, с тестовой instrumentation и read-only provider. Не распространять его вместо ARM64 APK. Тест создаёт отдельный Windows-профиль, работает с реальным relay и не меняет VPS. Не включать `.env_server`, `.local`, ключи, профили и SDK в архив исходников.
