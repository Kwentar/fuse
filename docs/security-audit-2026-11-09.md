# Fuse: аудит утечек перед публикацией — 2026-11-09

Источник: [REQ-2026-11-09-LEAK-AUDIT](../REQUESTS.md#req-leak-audit), TASK-AUDIT-001. Проверки: [RUN-2026-11-09-005](../RUNLOG.md#run-leak-audit).

Уточнение после аудита: по [PUBLISH-SOURCE](../REQUESTS.md#req-publish-source) публикуются только исходники, без готовых сборок и GitHub Releases. AUDIT-01 не блокирует этот этап: `dist` остаётся локальным. Для AUDIT-02 добавлены исключения записей передач, принятых файлов, `.atomic-*` и промежуточной Android-конфигурации; контрольные пути проверены. AUDIT-03–04 остаются рекомендациями для будущей упаковки и администрирования. Далее сохранён результат аудита до создания первого коммита; последующие действия фиксируются в RUNLOG.

## Вывод

В текущем составе исходников, отбираемом Git с действующим `.gitignore`, известных секретов, реальных адресов собственной инфраструктуры, личных путей, email и прежних посторонних организационных ссылок не обнаружено. `AGENTS.md` относится только к Fuse. Встроенные списки серверов пусты. По этой проверке исходники пригодны для первого публичного коммита после просмотра staged diff.

Однако вся рабочая папка не является безопасным комплектом для выгрузки: в 24 старых артефактах из `dist` подтверждены реальные адреса и Peer ID серверов. Они исключены из Git, но остаются в локальных файлах. Публиковать эти артефакты в Releases нельзя. Признаков того, что они уже были опубликованы, эта проверка не устанавливает.

Аудит не менял код, правила исключения или сборки и не устранял перечисленные ниже потенциальные риски. Он не является полной проверкой безопасности мессенджера.

## Объём и метод

- Проверены 106 файлов, доступных для обычного добавления в Git до создания этого отчёта: исходники, скрипты, конфигурации-примеры и документы. После добавления отчёта публикуемый состав составляет 107 файлов.
- Корневого Git-репозитория нет: отсутствуют коммиты, ветки, индекс и настроенный remote. Историю проверить невозможно. Для отбора файлов и проверки исключений использован отдельный локальный служебный Git-контекст, без инициализации Git в корне проекта.
- Выполнен поиск известных приватных значений, форматов ключей и токенов, email, URL с реквизитами, конкретных Peer ID, личных ссылок и путей. Девять строк с высокой энтропией просмотрены вручную: это названия тестовых проверок, типовые пути установки и SHA-256 пустого файла. Два совпадения шаблона пользовательского пути в README содержат заполнитель `YOUR_USER`, а не реальный аккаунт. Остальные IP в исходниках — примеры и тестовые данные.
- Дополнительно проверены 63 файла в `dist`, включая 787 элементов ZIP/APK с раскрытием вложенных архивов. Для бинарников искались известные приватные значения и абсолютный путь рабочей папки в UTF-8/UTF-16LE. Ошибок чтения и превышений установленного лимита распаковки не было. Это не универсальный поиск произвольных неизвестных секретов в бинарниках.
- Вручную прочитаны чувствительные участки: передача файлов и маршрутов, журналирование, хранение профиля, локальный IPC, Android-манифест, сборка, упаковка и административное SSH-подключение.
- `.env_server`, приватные SSH-ключи и пользовательская переписка не открывались. Проверка известных значений использовала ранее сохранённые локальные контрольные маркеры; сами значения в отчёт не включены.

## Находки

### AUDIT-01 — Адреса инфраструктуры сохранены в старых артефактах

**Приоритет: высокий для публикации бинарников и старых архивов. Статус: подтверждено локально; в текущий обычный коммит не попадает.**

Найдено 28 совпавших файлов/элементов архивов в 24 отдельных артефактах. Категории совпадений — адреса серверов и Peer ID; совпадений с известным паролем в этой проверке нет. Примеры: `dist/messenger.exe`, `dist/gui/messenger.exe`, `dist/p2p-messenger-0.1.0-source.zip` и старые Android APK. В архивах встречаются прежние `internal/config/default-network.json`, `configs/relay-new.json`, а также встроенные значения в исполняемом коде и Android assets.

Удаление адресов из текущего JSON не меняет уже собранный EXE/APK или сохранённый ZIP. Правило `dist/` исключает эти файлы из обычного добавления в Git, но не защищает от ручной загрузки или `git add -f`.

**Рекомендация:** не использовать старое содержимое `dist` для публичного релиза. Собирать нужные артефакты заново из проверенного дерева и проверять именно выдаваемые файлы. В проверенных `dist/windows-0.4/fuse.exe` и `dist/windows-0.4/messenger.exe` известных приватных значений и пути рабочей папки не найдено; это не заменяет приёмку релиза. Старые файлы в ходе аудита не удалялись.

### AUDIT-02 — Профиль в произвольной папке может частично попасть в Git

**Приоритет: средний. Статус: правило воспроизведено на контрольных именах; таких данных в текущем публикуемом составе нет.**

Каталоги `.local/`, `profiles/` и корневой `data/` исключены полностью. Но CLI позволяет выбирать каталог данных. Если создать профиль, например, в `demo/`, ключ и история будут исключены по имени, а `demo/files/*.json` и `demo/files/*.bin` останутся кандидатами для коммита.

В [internal/node/files.go](../internal/node/files.go), строки 27–58 и 68–71, локальная запись содержит Peer ID, имя файла, время и абсолютные `path`/`export_path`; принятые байты сохраняются в `files/*.bin` (строка 172). Проверка `git check-ignore --no-index` подтвердила: контрольные `demo/files/in-test.json` и `demo/files/test.bin` не исключены. Также не исключён `demo/.atomic-123`: временный файл записи создаётся в [internal/securefs/files.go](../internal/securefs/files.go), строка 30; после аварийного завершения он может остаться. Android использует промежуточный `config.android-next.json`, который также не защищён общим правилом имени при копировании профиля в произвольный каталог репозитория.

**Рекомендация:** хранить рабочие и тестовые профили вне исходников либо внутри `.local/`; дополнить защиту от характерных файлов профиля и временных записей. Не исключать все JSON без разбора: среди них есть необходимые исходные конфигурации.

### AUDIT-03 — Не все пути сборки проверяют встроенную сеть

**Приоритет: средний. Статус: условный риск повторного появления адресов; текущая конфигурация пустая.**

[internal/config/defaults.go](../internal/config/defaults.go), строка 8, встраивает `default-network.json` в бинарник. [scripts/build-android.ps1](../scripts/build-android.ps1), строка 22, дополнительно копирует его в APK assets. Проверка пустых списков существует в [scripts/package-source.ps1](../scripts/package-source.ps1), строки 6–8, но отдельный [scripts/package-desktop.ps1](../scripts/package-desktop.ps1), строка 5, напрямую вызывает сборку GUI без этой проверки.

Если временно записать свои адреса в исходный JSON для частной сборки, этот путь упаковки создаст публично выглядящий архив со встроенными адресами. Сам Git также не блокирует изменение содержимого отслеживаемого JSON.

**Рекомендация:** сделать проверку пустой публичной сети общей для всех публичных способов упаковки и проверки перед коммитом. Частные сетевые параметры хранить отдельно. Сейчас наличие пустого JSON подтверждено; повторная сборка ради аудита не выполнялась.

### AUDIT-04 — SSH-скрипт автоматически доверяет неизвестному ключу сервера

**Приоритет: средний при администрировании. Статус: поведение подтверждено чтением кода; атака не воспроизводилась.**

[scripts/server_check.py](../scripts/server_check.py), строки 37–45: `PinOnFirstUse` сохраняет впервые увиденный ключ без независимой проверки fingerprint, затем выполняется аутентификация паролем из локального файла. При подмене первого подключения клиент может отправить пароль атакующему серверу. Уже известный ключ проверяется; это не полное отключение проверки SSH.

**Рекомендация:** заранее проверять fingerprint по доверенному каналу и добавлять ключ в known_hosts, а неизвестные ключи отклонять. Это относится к административным скриптам и само по себе не является утечкой реквизитов в исходниках. SSH-скрипты и подключения к серверам во время аудита не запускались.

## Границы приватности самого приложения

Эти свойства следует учитывать при использовании, но они не означают найденную публикацию личных данных автора:

- **Сетевая идентичность не анонимна.** При smart routing запускается mDNS ([internal/node/node.go](../internal/node/node.go), строка 186); DHT получает подписанную запись Peer ID и адресов (строки 385–388). Обмен маршрутами передаёт сетевые адреса, включая LAN, а прямые соединения раскрывают адрес собеседнику. Шифрование содержимого не скрывает всю сетевую метаинформацию.
- **Данные профиля не зашифрованы на диске.** Ключ, история, пути и файлы защищаются правами ОС: Windows DACL либо Unix permissions. Процесс с правами владельца может их прочитать. Выбранная пользователем папка загрузок — отдельная область хранения с её собственными правами.
- **Оригиналы файлов передаются вместе с их метаданными.** Имя, размер и хеш входят в файловый протокол; EXIF/GPS внутри оригинала не удаляются. Локальные `path`, `export_path` и внутреннее состояние хеширования в структуру сетевого `fileRequest` не входят.
- **Журналы и CLI требуют аккуратного обращения.** Лог события содержит время, код и Peer ID ([internal/logging/log.go](../internal/logging/log.go), строка 55). Текст, введённый аргументом CLI, может сохраниться в истории оболочки; для чувствительного текста предусмотрен `--stdin`, используемый GUI. Профили, дампы IPC и сырые логи не следует прикладывать к публичным issues.

В просмотренном коде не найдены встроенные сервисы аналитики или отправка crash reports. Для транспорта явно настроен Noise; локальное управление использует защищённый IPC. Приём файлов проверяет наличие отправителя в контактах. Android запрещает системный backup приложения, сервис не экспортирован. Это положительные свойства прочитанного кода, а не доказательство отсутствия всех путей утечки.

Пароль `android` в скрипте подписи относится к локальному preview-keystore. Сам keystore исключён из Git; это не обнаруженный серверный секрет. Подпись производственного Android-релиза требует отдельного решения.

## Ограничения и дальнейшие действия

Проверка была статической, с разбором существующих артефактов и воспроизведением правил Git. Специализированные Gitleaks/TruffleHog не запускались; применялся локальный сканер и ручное чтение. Не выполнялись анализ CVE зависимостей, пентест, захват трафика, проверка внешних серверов, физических устройств и macOS. Предыдущие Go-тесты, go vet, Windows-сборка и компиляция Android Java записаны в [RUNLOG](../RUNLOG.md#run-publication-check); в этом аудите они заново не запускались.

Перед публикацией исходников нужно проверить фактический индекс первого коммита, включая имена файлов, содержимое и публичность автора/email коммита. Пока коммита нет, его метаданные не оценены. Загрузку всей рабочей папки следует исключить. Для публичных бинарников необходимо выполнить рекомендацию AUDIT-01. AUDIT-02–04 — отдельные рекомендации по предотвращению повторных утечек, пока без реализации.

Подробный список совпадений, контрольные хеши и технические результаты сохранены только в исключённой из Git `.local/publication-audit/`. Новых архивов, commit или push в ходе аудита не создавалось.
